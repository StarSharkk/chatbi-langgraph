# 淘宝用户行为数据：表结构与指标口径

## 数据背景
- 来源：阿里天池 UserBehavior，按 user_id % 10 = 0 抽取 10% 用户的全部行为，已清洗。
- 时间范围：2017-11-25 至 2017-12-03，共 9 天（北京时间）。
- 没有金额、价格、订单号字段；一行 = 一次行为。

## 表结构（数据库 taobao，MySQL）

### ub：用户行为明细（9,980,301 行）
| 字段 | 类型 | 含义 |
|---|---|---|
| user_id | INT | 用户 ID |
| item_id | INT | 商品 ID |
| category_id | INT | 商品类目 ID（只有数字，没有类目名称） |
| behavior_type | VARCHAR | 行为类型，只有 4 个取值：'pv' 浏览、'fav' 收藏、'cart' 加购、'buy' 购买 |
| ts | BIGINT | Unix 时间戳（秒），算时间间隔时用它相减 |
| dt | DATETIME | 行为时间（北京时间） |
| d | DATE | 行为日期，按天统计时用它 |
| h | TINYINT | 行为发生的小时，0–23 |

### user_rfm：购买用户的 RFM 分层（67,421 行，每个购买用户一行）
| 字段 | 含义 |
|---|---|
| user_id | 用户 ID，可与 ub.user_id 关联 |
| recency_days | 最近一次购买距 2017-12-04 的天数，越小越近 |
| frequency | 购买次数（buy 行数） |
| monetary_proxy | 购买过的不同类目数（没有金额，用它近似 M） |
| r_high / f_high / m_high | 0 或 1，是否高于购买用户均值（R 是"近于均值"记 1） |
| segment | 分层中文名，取值见下表，可直接用于过滤和分组 |

segment 与 CONCAT(r_high, f_high, m_high) 编码的对应关系：
| 编码 | segment |
|---|---|
| '111' | 重要价值客户 |
| '011' | 重要唤回客户 |
| '110' | 潜力客户 |
| '100' | 新客户 |
| '010' | 一般维持客户 |
| '000' | 流失风险客户 |
（'101' 重要深耕、'001' 重要挽留 在本数据中人数为 0）

## 指标口径（必须按这里的定义写 SQL）
- **PV**：behavior_type = 'pv' 的行数。
- **UV / 用户数**：COUNT(DISTINCT user_id)。
- **DAU**：某天 COUNT(DISTINCT user_id)，按 d 分组。
- **购买用户数**：有过 buy 行为的去重用户数。
- **付费率（用户转化率）**：购买用户数 / 全部用户数（UV）。
- **复购率**：购买次数 ≥ 2 的用户数 / 购买用户数。购买次数 = 该用户 buy 的行数。
- **购买转化率（行为次数口径，用于按小时/按天/按类目比较）**：buy 行数 / pv 行数。
- **加购用户购买率（用户口径）**：既有 cart 又有 buy 的用户数 / 有 cart 的用户数；不要求购买发生在加购之后，也不要求是同一商品，除非问题明确要求。
- **商品级路径转化（用户×商品口径）**：按 (user_id, item_id) 分组，看该组合是否有 fav / cart / buy，转化率 = 有 buy 的组合数 / 组合数。问题里出现"同一商品""商品级"时用这个口径。
- **加购到购买的间隔**：同一 (user_id, item_id) 上，首次 buy 的 ts − 首次 cart 的 ts（秒），只统计 buy 晚于 cart 的组合。
- **次日留存（活跃日口径）**：在 d 日活跃的用户中，d+1 日也活跃的比例。N 日留存同理（d+N）。
- **类目购买集中度**：按 category_id 统计 buy 行数后排序计算占比。

## 已知数据偏差（解释结果时要提醒）
- 12-02、12-03 两天活跃用户占全部用户约 98%，说明样本是按"这两天活跃"挑选的。任何落在 12-02/12-03 的留存都会被抬高到 95% 以上，整体付费率（约 68%）也偏高，不代表淘宝真实水平。
- M 用类目数近似，不是真实消费金额。

## SQL 书写规则
- 只写一条 SELECT 语句（可以用 WITH），不要写任何修改数据的语句。
- 只能使用上面列出的两张表和字段，不要编造表名或字段名。
- 比例用 ROUND(x, 4) 保留 4 位小数。
- ub 有近 1000 万行，尽量先聚合再关联，避免对全表做相关子查询。
